## 작성 요령

- 아래 목차와 항목 순서를 그대로 따라 작성합니다. 각 항목 아래의 안내 문구는 작성 후 삭제합니다.
- 그래프에는 축 이름과 단위(µs, ms, MB/s 등)를 반드시 표시하고, 같은 조건의 3가지 IPC는 한 그래프에서 비교합니다.
- 모든 수치는 직접 측정한 값이어야 하며, 측정 조건(메시지 크기, 클라이언트 수, 반복 횟수)을 함께 적습니다. 일반적인 IPC 특성 설명이 아니라 직접 측정한 수치를 근거로 설명해야 분석 점수로 인정됩니다.
- 3장의 성능 예측은 구현과 측정 전에 작성한 내용을 그대로 싣고, 이후 수정한 부분이 있으면 무엇을 왜 바꿨는지 따로 표시합니다.

## 1. 문제 정의 및 요구사항 분석

### 1.1 문제 정의 및 설계과제 목표

- 어떤 응용을 왜 기획했는지, 이 응용이 해결하는 문제는 무엇인지 기술합니다.
- 이 응용에서 IPC 선택이 성능에 중요한 이유를 설명합니다.

### 1.2 요구사항 분석

- 기능 요구사항: 클라이언트와 서버가 수행하는 기능을 나열합니다.
- 비기능 요구사항: 동시 클라이언트 수, 목표 응답시간이나 처리량 등 성능 관련 요구사항을 정량적으로 제시합니다.
- 제약 조건: 프로세스별 3개 이상 스레드, 클라이언트 2개 이상 동시 실행, make 사용, IPC 자원 정리 등 과제 조건을 어떻게 충족하는지 기술합니다.

## 2. IPC 기초 성능 측정 (1단계)

### 2.1 측정 환경


| 항목                             | 내용 |
| ---------------------------------- | ------ |
| CPU 모델 / 코어 수               |      |
| 메모리                           |      |
| OS 배포판 / 커널 버전            |      |
| gcc 버전                         |      |
| 가상화 여부 (네이티브, VM, WSL2) |      |

### 2.2 벤치마크 설계

- 3가지 IPC 벤치마크의 구조와 측정 방식(ping-pong 지연, 처리량)을 설명합니다.
- 타임스탬프를 찍은 위치와 그 이유, 워밍업과 반복 횟수를 기술합니다.

### 2.3 측정 결과

- 메시지 크기별 왕복 지연시간 그래프 (3가지 IPC 비교)
- 메시지 크기별 처리량 그래프
- 클라이언트 수별 지연시간과 처리량 그래프
- 평균, 중앙값, 최대값(또는 상위 99%)을 함께 제시합니다.

### 2.4 결과 해석

- 어느 조건에서 어떤 IPC가 유리했는지, 순위가 바뀌는 지점이 있었는지 설명합니다.
- 그 이유를 IPC의 동작 원리(데이터 복사 횟수, 시스템 콜, 동기화 비용)와 연결해 설명하고, 가능하면 strace -c, getrusage() 등의 근거를 제시합니다.
- 예상과 다른 결과가 있었다면 무엇이었고, 왜 그렇다고 보는지 씁니다.
