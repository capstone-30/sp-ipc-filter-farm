# 데모·시스템 콜·공정성 분석 — IPC Filter Farm

2026-11-13(한국 시각)에 데모·진단 10회의 정합성과 이미지·CSV I/O 제외를 확인했다. 제어·런타임 파일 접근과 측정 후 R3 정정은 [아래 판정](#r3-공정성-판정)에 공개한다.

## 데모 정합성

10개 실행의 총 2,000개 측정 표본에서 seq=10..109, ID, 196,608B 페이로드, 양수 RTT와 클라별 `matched=100 mismatches=0`, 서버 `responses=200`을 확인했다. 40개 PPM은 256²·P6·3채널이며, GRAY 반올림과 clamp 경계 Sobel을 독립적인 Python 참조 계산으로 전 바이트 대조했다. EDGE 참조는 구현의 이진 탐색 대신 직접 제곱근을 사용했다. 생성 입력의 그라데이션·격자 패턴도 전 바이트 일치했다. 입력과 출력은 달랐고 두 클라의 결과가 섞이지 않았다. RTT 백분위·평균·처리량과 CPU·컨텍스트 스위치·RSS를 원자료에서 독립 재계산해 각 실행의 집계와 대조했다. 모든 stderr가 비었으며 각 실행 후 본인 소유 MQ·SHM·SEM은 없었다. 다른 계정의 IPC 객체는 검사 실패나 정리 대상으로 취급하지 않았다.

## 시스템 콜 비교

summary는 **시작·워밍업·측정·종료 전체**를 추적한다. pipe에는 launcher까지 포함되고 MQ/SHM은 서버·클라 세 요약을 합산했다. 아래 횟수는 같은 관측 범위의 IPC 경로 특성을 설명하며, 정식 RTT나 처리량에 합치지 않는다.

| 호출 | pipe | sysv_mq | sysv_shm |
| --- | ---: | ---: | ---: |
| 전체 | 9,024 | 52,865 | 8,533 |
| read / write | 1,949 / 2,758 | 10 / 20 | 12 / 20 |
| poll | 2,030 | 0 | 0 |
| msgsnd / msgrcv | 0 / 0 | 16,826 / 17,902 | 0 / 0 |
| semtimedop | 0 | 0 | 3,165 |
| clock_nanosleep | 377 | 13,935 | 1,065 |
| futex | 1,265 | 1,476 | 1,475 |

MQ의 `msgsnd/msgrcv` 오류 반환은 각각 5,824/6,900회다. 성공 호출은 각각 11,002회이며 25청크씩의 220개 요청·220개 응답과 BYE 2개에 부합한다. SHM의 `semtimedop` 오류 반환은 1,397회다. 재시도 경로와 부합하지만 summary만으로 모든 errno를 확정하지 않는다. 오류 반환 횟수는 최종 메시지 유실 건수가 아니다.

이 결과는 MQ의 청크 처리와 비차단 재시도 비용, SHM의 세마포어 동기화, pipe의 read/write/poll 경로와 부합한다. 시스템 콜 시간에는 추적 간섭과 대기가 포함되며 서로 다른 스레드의 시간이 겹칠 수 있다. 이를 벽시계 시간 비율이나 커널 복사 비용의 기여율로 해석하지 않는다. SHM의 사용자 공간 memcpy·체크섬 비용은 strace에 직접 나타나지 않는다.

## R3 공정성 판정

확장 추적은 `openat/read/write/pread64/pwrite64/close/getrusage`와 프로세스·스레드 생성 호출을 수집한다. unfinished/resumed를 재결합하고 `CLONE_THREAD`를 같은 프로세스로 묶어, 각 프로세스의 두 `getrusage(RUSAGE_SELF)` 사이를 판정했다. CSV의 시각은 원본 trace 표기를 그대로 보존한다.

9개 CPU 구간 모두 이미지·CSV I/O가 없었으며 `/proc/self/status`의 RSS 읽기는 해당 프로세스의 구간 밖에 있었다. 그러나 다른 일반 파일 I/O가 있었다.

| IPC | 서버 meta 읽기 / 쓰기 | 클라 1·2 meta 읽기 | 그 밖의 구간 내 접근 |
| --- | ---: | ---: | --- |
| pipe | 0 / 1 | 0 / 0 | 없음 |
| sysv_mq | 403 / 25 | 200 / 200 | 서버의 `/proc/sys/vm/overcommit_memory` open/read 각 1회 |
| sysv_shm | 787 / 1 | 200 / 200 | 없음 |

메타데이터 접근 대상은 `key.meta`이며 ID 퇴역·상태 확인에 사용한다. MQ 서버의 `/proc/sys/vm/overcommit_memory` 읽기는 메모리 할당 경로에서 발생한 것으로 추정하지만 호출 스택을 수집하지 않았으므로 원인을 확정하지 않는다. pipe도 클라별 종료 시점이 달라 서버 CPU 구간 안에 ID 퇴역 쓰기가 포함됐다.

과제 [안내문 5절](assignment-guide.md#5-측정-방법-필수-요건)과 [서식](final-report-template.md)은 간섭 최소화·영향 설명을 요구하며 파일 I/O 전면 금지·비교 전체 무효를 명시하지 않는다. 포괄 금지는 프로젝트 자체 조건으로 최초 커밋 `0500b33`부터 확인되며 이전 시점·작성 주체는 미확인이다.

변경 전 문구를 모든 일반 파일 접근 금지로 읽으면 추적은 불충족이다. 기존 검증은 이미지·CSV만 검사했고 상대 확인을 포함한 구현 비용을 측정했으므로, 이를 원본 과제 위반·전체 무효로 단정한 해석은 정정한다.

2026-11-13 측정 후 [R3](01-func/01-requirements.md#측정-공정성)를 이미지·결과·CSV I/O와 진행 출력 제외, 제어 메타데이터·런타임 조회 비용 포함·공개로 명확히 했다. 기존 측정의 변경 전 충족을 소급하지 않았으며 측정값·경계·과제 원문은 바꾸지 않았다.

결과는 해당 서버·구현의 전체 경로 비용으로 해석한다. 제어 파일 비용은 차감하지 않으며 순수 IPC 비용이나 일반 파일 접근 부재를 주장하지 않는다. MQ의 추가 /proc 조회 기여율은 미분리다. 메타데이터·조회 경로를 최적화하면 별도 개선 실험으로 재측정한다.
